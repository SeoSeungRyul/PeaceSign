# 물 타일과 낚싯대 기초

## 조작

- `[`를 누르면 개발용으로 게임 날짜가 28일 진행되어 다음 계절을 바로 확인할 수 있다.
- `3`: 낚싯대 장착. 기존 `0` 맨손, `1` 괭이, `2` 씨앗은 유지한다.
- 육지에서 상하좌우 직선으로 최대 2칸 또는 대각선으로 1칸 떨어진 물칸에 커서를 놓고 우클릭한다. `F`도 같은 판정을 사용한다.
- 낚싯대 장착 시 대상 테두리는 사용 가능하면 초록색, 불가능하면 빨간색이다.
- 유효한 사용 시 `OnFishingRodUsed` 이벤트를 한 번 전달하고 낚싯줄과 찌를 계속 디버그 표시한다.
- 우클릭으로 준비한 뒤 캐스팅 게이지에서 우클릭을 새로 눌러 투척한다. `F`는 투척 게이지를 확정하지 않는다.
- 캐스팅하면 장비 변경을 잠근다. 입질 대기 중 이동키, `F` 또는 우클릭을 누르면 찌 회수를 시작하며, 회수 모션이 끝난 뒤 이동과 도구 사용을 허용한다. 미니게임 중 이동키는 방향 입력으로 사용한다.
- 대각선 2칸, 가로 2칸·세로 1칸 등의 범위 밖 물칸, 땅, 월드 밖, 물 위에서의 사용은 거부한다.

## 호수 생성

- TestMap에는 낚시 시험용 8×8 호수를 시작 지점 위쪽(+X)에 배치했다. 가운데 2×2는 풀섬이며, 바깥에 한 칸의 풀 테두리를 둔다. Grid World의 `Fishing > Enable Fishing Test Pond`, `Fishing Test Pond Origin`으로 설정한다. 일반 맵의 기본값은 꺼짐이다. 에디터 미리보기와 플레이 중 지형에 모두 적용하며, 기존 저장 지형에도 해당 영역만 반영한다. 테스트 영역은 저장되므로 옵션을 꺼도 이미 저장된 호수는 남는다.

- 물은 파란색 타일이다. 8×8 영역마다 시드에 따라 35% 확률로 가로·세로 각각 2~4칸인 호수를 만든다.
- 호수 사이에는 육지를 남긴다. 시작점 주변과 월드 경계에서 호수 전체가 들어가지 않는 경우에는 생성하지 않는다.
- 물에는 밭을 갈거나 씨앗을 심을 수 없다.
- 기존 enum 값 뒤에 Water와 FishingRod를 추가해 이전 값의 번호를 유지한다.
- 기존 저장 청크의 땅과 호수가 겹치면 그 호수 전체를 생성하지 않는다. 저장된 농사 데이터를 유지하며, 청크 경계에서 호수가 잘리는 것을 방지한다.
- 기존 저장 지역에는 호수가 보이지 않을 수 있다. 새 영역을 확인하거나, 기존 데이터를 지워도 되는 경우에만 `R`로 월드를 초기화한다.
- 에디터의 저장된 미리보기는 Grid World의 `Generate Grid Preview`로 다시 생성한다.

## 낚시 진행

- 투척이 확정되면 실제 찌 착수 위치를 기준으로 카메라가 기본 1.2초 동안 이동한다(2026-11-03 사용자 지시). 출발·도착의 속도와 가속도가 0인 5차 전환 곡선으로 천천히 출발해 가속하고, 도착 시 감속한다. 입질 대기·챔질 대기·화살표 미니게임 동안 유지하며, 취소·성공·실패 시 같은 방식으로 캐릭터 기준으로 복귀한다. 성공 결과 모션으로 이동이 잠긴 동안에도 복귀한다. 스프링암 오프셋을 수정하는 대신 `CalcCamera`에서 실제 출력 시점에 평면 이동을 적용한다. 원래 카메라 오프셋·높이·각도·Ortho Width를 유지하며 조종을 잃으면 이동값을 초기화한다. `BP_PSPlayerCharacter > Class Defaults > Fishing|Camera > Fishing Camera Blend Seconds`로 전환 시간을 조절하며 0이면 즉시 전환한다. 일시정지 시 전환도 멈춘다. `Scripts/SlowFishingCamera.py`로 해당 캐릭터 BP 기본값에 1.2초를 저장한다.
- 입질을 기다리는 1~10초 동안 대기 시간 바와 빈 미니게임 패널은 표시하지 않는다. 내부 대기 시간과 미끼 효과는 유지한다. 입질이 오면 `!` 말풍선을 표시하고, 화살표 미니게임을 시작하면 제한시간 바를 표시한다.
- 낚시 카메라와 입질·미니게임 UI는 `GetFishingFocusLocation`의 같은 찌 좌표를 사용한다. 느낌표는 별도의 `BiteOffset`(기본 0, -24)으로 찌 바로 위에 표시한다. 따라다니는 패널은 UI 배율을 반영해 화면 안으로 보정한다. 투척 준비와 사용 불가 안내는 캐릭터를 기준으로 표시하며 결과창은 기존 화면 고정 위치를 사용한다.
- UE 5.8 직교 카메라의 자동 클리핑 보정은 카메라와 캐릭터 사이의 전체 벡터를 최종 화면 원점에 더한다. 따라서 `CalcCamera` 출력만 이동시켜도 실제 화면은 다시 캐릭터로 고정될 수 있다. `APSPlayerController::UpdateCameraManager`에서 이 보정 벡터를 카메라 시선 방향의 깊이 성분으로 제한해 가로 이동을 보존한다. 자동 근거리·원거리 클리핑과 확대 비율은 유지한다. 회귀 검증은 카메라 캐시뿐 아니라 최종 직교 투영과 찌의 화면 중앙 좌표까지 확인한다.

- 10월 21일 기획에 따라 캐스팅 준비 모션은 첫 두 스프라이트(플립북 키프레임)까지만 재생하고 두 번째 스프라이트에서 대기한다. `BP_PSPlayerCharacter`의 `Fishing|Animation > Fishing Cast Flipbook`에 전체 투척 플립북을 지정하면 앞 두 키프레임의 길이로 준비 시간을 계산한다. 투척 확정 시 세 번째 키프레임부터 이어 재생하며, 취소·종료 시 이전 애니메이션 상태를 복구한다. 플립북이 없거나 두 키프레임 미만이면 기존 `CastWindupDuration`(기본 0.35초)을 사용한다. 현재 프로젝트에는 전용 낚시 캐릭터 플립북이 없어 실제 리소스 지정은 별도로 필요하다.
- 준비 후 막대가 가로 게이지의 왼쪽에서 오른쪽까지 0.7초에 이동하며 계속 왕복한다. 구간은 초록·노랑·빨강·노랑·초록이며 중앙 빨강이 최대 거리다. 10월 26일 문서 기준으로 가로 비율은 왼쪽부터 20/15/30/20/15%다. `CastBands`에서 다섯 구간의 비율을 각각 편집하며 준비 시작 시 고정한다. 표시와 판정은 같은 경계값을 사용한다.
- 투척 후 1~10초 사이에 입질이 발생하며, 입질 후 5초 안에 `F` 또는 우클릭을 눌러야 한다. 일시정지 시 게이지와 제한시간도 멈춘다.
- 미니게임은 10초 동안 화면의 화살표 순서를 입력한다. 오답은 현재 순서를 유지하고 남은 시간을 0.5초 줄이며, 키 반복 입력은 받지 않는다.
- 난이도 1~4에 따른 입력 개수는 각각 5~10, 11~20, 21~30, 31~40개다.
- 성공 시 어종과 크기를 표시하고 물고기를 가방에 추가한다. 가방이 가득 차면 플레이어 옆에 줍을 수 있는 물고기를 떨어뜨린다.
- 기본 어종은 붕어, 잉어, 메기, 황금 잉어다. `FishDataTable`을 지정하면 데이터 테이블 행을 우선 사용한다.

## 투척 거리와 확률

10월 21일 기획서를 적용한다. 초록 2m(2타일), 노랑 4m(4타일), 빨강 6m(6타일)이다. 최초 사용 시에는 기존 물가 거리 조건을 확인하고, 고정한 방향으로 던진다. 찌는 투척 경로의 육지·섬·장애물을 관통하며, 중간에 멈추지 않는다. 목표 착수 타일이 물이면 그 타일에 착수한다.

목표가 물이 아니면 플레이어 기준 반경 6타일 안에서 목표 착수점에 가장 가까운 물 타일을 선택한다. 후보 타일 중심까지의 평면 거리를 사용하며, 동률은 Y가 작은 칸, 그다음 X가 작은 칸 순으로 고정한다. 이 기준점과 동률 규칙은 기획서의 미정 부분에 대해 이번 구현에서 정한 기준이다. 범위 안에 물이 없으면 낚시를 취소하며 미끼·내구도를 소모하지 않는다. 보정 후에도 판정 색상에 따른 난이도 확률을 유지한다.

`DT_FishingCast`는 `FPSFishingCastDefinition` 행 구조이며 `Green`, `Yellow`, `Red` 세 행을 사용한다.

| 행 | DistanceInCells | DifficultyWeights (난이도 1~4) |
|---|---:|---|
| Green | 2 | 55, 30, 13, 2 |
| Yellow | 4 | 50, 30, 15, 5 |
| Red | 6 | 45, 30, 17, 8 |

계절·실제 착수 장소에 맞는 어종을 모은 뒤 난이도를 먼저 추첨하고, 해당 난이도 안에서 Fish 테이블의 `Weight`로 어종을 추첨한다. 어종 수나 어종별 가중치가 난이도 확률을 바꾸지 않는다. 후보가 없는 난이도는 제외하고 남은 난이도 확률을 재계산한다. `Weight`가 0 이하이거나 유효하지 않으면 추첨하지 않는다. 투척 설정 행이 잘못되거나 누락되면 해당 색상의 기본 설정을 사용한다.

장비 효과·계절·투척 설정은 준비 시작 시 고정된다. 어종 선택과 미끼 소모는 투척 확정 시 수행한다. 준비 중 취소하거나 실제 투척이 불가능하면 미끼와 내구도를 소모하지 않는다.

## 낚시 UI 편집

새 시안의 위젯 이름·타입·이미지 연결은 [낚시 UI 연결 방법](FishingUI.md)을 참고한다. 실제 WBP는 7칸과 현재 입력 4번째 칸으로 이관했다. 일반 실행은 Designer 배치를 다시 만들지 않는다.

`/Game/UI/Fishing/WBP_Fishing`을 열면 Designer에서 패널 크기·간격·배경 이미지를 편집할 수 있다. 코드가 기존 디자이너 트리를 다시 만들지 않는다. 상태 연결에 사용하는 위젯 이름과 타입은 유지한다.

- `FishCastPanel`: 투척 게이지. `FishCastTrack`, `CastGreen`, `CastYellow`, `CastRed`, `CastYellowRight`, `CastGreenRight`, `CastMarker`(Image), `CastLabel`을 포함한다.
- `FishMinigamePanel`: `StateLabel`, `TimeBar`, `FishDirectionRow`와 0~6번 `FishDirectionBox`, `DirectionImage`, `DirectionMarker`을 포함한다.
- `FishResultPanel`: 왼쪽 아래 결과 팝업. `ResultIcon`, `ResultNameLabel`, `ResultSizeLabel`, `ResultLabel`을 포함한다. 이름·크기 위젯이 없는 구형 WBP는 기존 한 줄 결과로 표시한다.
- `FishNoticePanel`: 실패 사유와 머리 위 X 안내. `NoticeLabel`을 포함한다.
- `FishBitePanel`: 입질 때 머리 위에 표시하는 노란 느낌표 말풍선. 표시부터 5초 안에 F/우클릭으로 챔질한다.

Class Defaults의 `Fishing|Art`에서 네 방향 일반 화살표, 현재·완료 화살표 세트, 일반·현재·완료·오입력 칸 브러시와 삼각형·투척 막대 브러시를 변경한다. `VisibleDirectionSlots`는 기본 7이고 `CurrentDirectionSlot`은 기본 3(네 번째 칸)이다. 오입력은 기본 0.2초 동안 현재 칸만 빨갛게 표시하며 정답 입력 시 즉시 해제한다. `Fishing|Layout`의 `MinigameOffset`, `CastingOffset`, `NoticeOffset`으로 플레이어 기준 위치를 조절한다. 화면 고정 UI로 바꾸려면 `Follow Player`를 끄고 Designer의 Canvas 위치를 사용한다. 결과 팝업은 Designer의 왼쪽 아래 앵커를 사용한다.

`Scripts/CreateFishingWidget.py`는 최초 위젯과 투척 테이블을 생성하고 `BP_PlayerController`에 연결한다. 재실행해도 기존 레이아웃과 테이블 값은 덮어쓰지 않는다. 낚시 불가 안내는 `OnFishingUnavailable` 이벤트에서 효과음을 추가로 연결할 수 있다.

`Scripts/SetupFishingPrototype.py`는 10월 23일 임시 UI의 실제 WBP를 가로형 기본 레이아웃으로 다시 만들고 TestMap 시작 위치 위쪽에 시험 호수를 설정하는 일회성 작업이다. 이 스크립트는 WBP 배치를 초기화하므로 사용자가 새 UI를 직접 편집한 뒤에는 재실행하지 않는다. 게임 실행 중에는 레이아웃을 다시 만들지 않는다.

## CSV 데이터 테이블 가져오기

물고기 CSV는 Unreal에서 행 구조를 `FPSFishDefinition`으로 선택한다. 첫 번째 열은 데이터 행 ID이며 헤더는 `---`를 사용한다.

```csv
---,Name,Difficulty,Season,Location,MinSize,MaxSize,Description,DescriptionPlus,IconID
010201,붕어,1,0,"(1,2)",10,40,기본 설명,최대 크기 설명,070201
```

CSV에는 위 영문 헤더 한 줄과 실제 물고기 행만 둔다. 엑셀의 한국어 제목 행과 `Int`, `String` 타입 설명 행은 삭제해야 하며 별도 `ID` 열을 만들지 않는다. 첫 번째 `---` 열의 값이 Unreal DataTable의 `Row Name`이 된다.

- `Season`: 0 봄, 1 여름, 2 가을, 3 겨울
- 한 계절은 28일이며 1~28일 봄, 29~56일 여름, 57~84일 가을, 85~112일 겨울 순서로 반복된다.
- `Location`: 0 바다, 1 강, 2 호수다. 정수 배열이며 CSV에서는 `"(1,2)"`처럼 괄호로 감싸고 쉼표가 있으면 셀 전체를 큰따옴표로 감싼다. 현재 절차 생성 물 타일은 호수로 판정한다.
- `IconID`: Icon 데이터 테이블의 행 ID를 참조한다.
- `Weight`: 선택 열이다. 생략하면 모든 행이 기본 가중치 1을 사용한다.
- 크기 범위, 난이도 또는 계절 값이 잘못된 행은 런타임 추첨 대상에서 제외하고 로그 경고를 남긴다.

아이콘 CSV는 행 구조를 `FPSIconDefinition`으로 선택한다.

```csv
---,Name,Image
070201,더미물고기,"Texture2D'/Game/UI/Icons/T_FishDummy.T_FishDummy'"
```

가져온 두 데이터 테이블을 `BP_PlayerController`의 `Fish Data Table`과 `Fish Icon Data Table`에 각각 지정한다. 성공 UI는 선택된 물고기의 `IconID`로 아이콘 행을 찾아 `Image` 텍스처를 표시한다. 이미지 경로가 비어 있거나 행을 찾지 못하면 아이콘 영역을 숨긴다. 획득한 물고기 스택에는 Fish 데이터 테이블의 행 ID가 `ItemId`로 보존되어 어종별로 따로 중첩된다.

물고기 추첨은 현재 게임 계절과 낚시한 물의 장소 ID가 모두 맞는 행만 사용한다. 조건에 맞는 행이 없으면 캐스팅을 시작하지 않는다. 인벤토리와 Hotbar는 `ItemId`로 물고기 행을 다시 찾아 어종 이름, 설명과 같은 아이콘을 표시한다. 추가 설명은 최대 크기 달성 후에만 표시한다.

성공한 낚시는 낚시 경험치 2를 준다. 실패와 취소는 경험치를 주지 않는다.

물 타일에는 보이지 않는 Pawn 전용 충돌 상자를 생성한다. 걷기·달리기·구르기의 경로 충돌 검사로 물 진입을 막으며, 청크 재생성·제거 시 충돌도 갱신한다. 충돌 높이는 청크 기준 Z -1000~1000이다. 낚시의 커서 판정에는 영향을 주지 않는다.
