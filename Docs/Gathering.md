# 채집 첫 구현

2026-10-30 구현 범위는 참나무·단풍나무, 도끼 9단계 데이터, 벌목·나무 흔들기, 원목·씨앗 드롭과 정상 저장·복원이다. 기준은 `GatheringPlan.md`의 첫 단계다.

2026-11-02: Item·TreeCutDrop·TreeShakeDrop CSV 테이블을 TestMap에 연결했다. 파일 준비와 Row Type, 재가져오기 절차는 `TreeDataTables.md`를 참고한다. 이 세 테이블을 연결한 월드는 아래의 확률 보상을 사용하고, 모두 비워둔 개발용 월드만 이전 고정 보상을 유지한다.

## 플레이 확인

- 새 게임의 단축바 9번에 내구도 100의 1단계 도끼를 지급한다. 기존 인벤토리는 9번, 다른 빈 단축바, 열린 빈 가방 순으로 지급한다. 공간이 없으면 지급을 보류하고 빈칸이 생겼을 때 보충한다.
- 테스트 나무는 그리드 기준 X=-20~-5, Y=6~21 영역에 생성한다. 서쪽은 참나무 중심, 동쪽은 단풍나무 중심이며 80%/20%로 수종을 선택한다. 물·돌·작물·경작지·타일 스탬프·거점 보호 영역과 필수 경로에는 생성하지 않는다.
- 도끼로 나무를 우클릭하면 0.6초간 작업한다. 0.3초 시점에 피해·SP·내구도를 한 번 적용한다. 기본 나무 HP는 60이며 1단계는 6회 타격한다.
- 도끼 외 장비로 나무를 우클릭하면 0.8초간 흔들고, 최초 시도와 마지막 유효 추첨부터 게임 7일 경과 시 다시 추첨한다. 흔들기는 SP·장비 내구도를 소모하지 않는다. 꽝도 유효 추첨으로 처리한다.
- 연결한 CSV 기준 벌목은 원목 3~6개 중 하나와 씨앗 0~2개 중 하나를 각각 추첨한다. 흔들기는 씨앗 1개 40%, 사과 1~5개 각각 3.2%, 밤 1개 24%, 꽝 20% 중 하나를 선택한다. 벌목의 보상 기록은 마지막 타격에 확정하고 화면의 드롭은 쓰러짐 연출이 끝난 뒤 나타난다.
- 가까이 가면 바닥 아이템을 줍는다. 가방이 차면 바닥에 남고, 같은 위치에서 공간을 확보해도 다시 수집을 시도한다. 현재 한 보상 스택을 전부 넣을 공간이 있을 때 수집한다.
- 이동·장비 교체는 작업 중 제한한다. 책을 열거나 포커스를 잃으면 진행 중 작업을 취소한다. 타격 전 취소는 무소모, 타격 후 취소는 이미 적용된 결과를 유지한다.

이동 범위는 직선 두 칸·대각선 한 칸이다. 물·오브젝트·물리 벽 너머의 작업은 막는다. 나무의 수관이 아닌 줄기 셀에 커서를 두어야 한다. 나무를 클릭한 입력은 기존 농사·낚시·삽 동작으로 넘기지 않는다.

## 데이터 편집

`Scripts/CreateGatheringPrototype.py`가 `/Game/DataBase/DT_Axe`와 `/Game/Art/Gathering/M_GatheringColor`를 최초 생성한다. 재실행은 기존 테이블과 재질의 사용자 수정 내용을 덮어쓰지 않는다. Item·TreeCutDrop·TreeShakeDrop 연결은 `Scripts/ImportTreeTables.py`를 사용한다.

2026-11-02: 이전 수종 테이블은 기본 HP 60과 이미 대체된 고정 보상만 보관하고 있어 제거했다. 나무 HP는 GridWorld > Gathering > Trees > Tree Max Health에서 편집하며 기본값은 60이다. 변경은 새로 생성된 나무부터 적용되고, 저장된 나무의 남은 HP는 유지한다. 수종별 드롭 그룹 번호는 `PSGathering::GetTree`에서 지정하며 보상 내용은 CSV 두 드롭 테이블에서 편집한다. `DT_Axe`의 Axe.Tier1~Axe.Tier9 행에서 피해량·SP·추가 목재 확률을 편집한다. 작업 시작 시 수치를 고정한다.

도끼 피해량은 10/12/15/15/20/20/30/30/60이다. 4단계 이상은 독립 20% 판정으로 원목 1개를 추가하며, 6단계 이상은 SP 5를 소모한다. 내구도는 유효 타격당 1을 소모한다. 8단계 희귀 부산물은 아이템·확률이 정해지지 않아 아직 추가하지 않았다.

## 저장과 호환

월드 저장 버전 6은 기존 그리드·농사 데이터를 유지하고 나무 좌표·수종·남은 HP·흔들기 가능 시각·보상 순번과 미수집 드롭을 함께 기록한다. 청크 렌더러와 별도로 나무 상태를 소유하므로 화면에서 멀어져 표현 액터가 사라져도 상태는 유지된다. 드롭 액터 생성에 실패해도 보상 기록은 남아 다시 시도한다.

기존 저장에는 명시한 개발용 테스트 구역에만 나무를 보충하며, 실제 저장된 땅과 오브젝트의 점유 상태를 확인한다. 최초 배치가 완료된 저장은 다시 실행해도 나무를 재생성하지 않는다. 개발용 R 초기화는 나무·미수집 채집 드롭도 초기화하므로 플레이 저장 검증에는 사용하지 않는다.

정상 저장·재접속을 지원한다. 기존 인벤토리와 월드는 서로 다른 파일에 저장되므로 두 파일 쓰기 사이 강제 종료까지 원자적으로 보장하지는 않는다. 이를 보장하려면 공통 스냅샷 또는 복구 기록을 추가해야 한다.

## 다음 단계
