# 채집 첫 구현 리뷰

2026-10-30. 참나무·단풍나무, 도끼, 벌목·흔들기, 보상과 정상 저장·복원을 대상으로 구현 코드를 재검토하고 자동화·실제 게임 실행으로 확인했다. 이 문서는 첫 구현 범위의 결과이며 전체 채집 콘텐츠의 완성을 의미하지 않는다.

## 리뷰에서 보완한 부분

| 항목 | 처리와 검증 |
| --- | --- |
| 나무 클릭과 기존 도구의 충돌 | 농사·낚시 분기 전에 나무 대상을 처리한다. 도끼 외 장비는 흔들기를 수행하고 기존 도구 사용으로 넘어가지 않는다. |
| 중복 보상 | 나무 HP 0에서 재타격을 차단한다. 흔들기는 지급 시각에 7일 쿨타임을 기록하고, 드롭 ID가 수집된 뒤 다시 처리되지 않게 한다. |
| 마지막 도끼 내구도와 이동 잠금 | 장비 변경 시 실제 낚시 중일 때만 낚시 종료 처리를 호출한다. 도끼가 부서져도 남은 작업 시간 동안 이동 잠금이 유지되는지 검증했다. |
| 작업 취소 | 책 열기·입력 포커스 변경·사망·대상 및 도구 변경으로 작업을 취소한다. 타격 전에는 소모하지 않고, 타격 후 결과는 다시 적용하지 않는다. |
| 거리와 장애물 | 셀 범위, 중간 물·오브젝트, 대각선 모서리와 물리 벽을 검사한다. 충돌 조회에서 작업자 자신의 캐릭터와 대상 나무는 제외한다. |
| 보상 생성 실패·가방 부족 | 액터보다 보상 기록을 먼저 저장한다. 스폰 실패는 다시 시도하며 가방 부족은 기록을 지우지 않는다. 지속적으로 겹친 아이템도 다시 수집을 시도한다. |
| 구버전 도끼 지급 | 기존 아이템을 덮어쓰지 않고 지급 보류 상태를 저장한다. 빈칸이 생긴 뒤 한 번만 지급하는지 검증했다. |
| 개발용 시각 구분 | 화면에서 수종이 회색으로 보이는 문제를 확인해 색상 매개변수가 있는 전용 재질을 추가했다. 참나무는 초록, 단풍나무는 주황으로 구분된다. |
| 후속 애니메이션 연결 | `GatheringAction.OnStarted`와 `OnFinished`를 Blueprint에서 바인딩 가능한 이벤트로 제공한다. |

## 검증 결과

- UE 5.8 `PeaceSignEditor Win64 Development` 최종 빌드 성공.
- 실제 렌더링 환경에서 `PeaceSign.` 자동화 테스트 **27개 성공, 실패 0개**. 신규 채집 검사와 기존 농사·낚시·채광·인벤토리·스킬·시간·도감 검사를 포함한다.
- `PS.Gathering.Smoke`로 TestMap에서 실제 플레이어가 나무 한 그루를 벌목하고, 이동 잠금 해제와 원목·씨앗 보상 기록을 확인했다.
- 생성 전·벌목 후 PNG를 열어 수종 색상, 그루터기, 드롭과 도끼 단축바 표시를 확인했다.
- 데이터 에셋 생성 스크립트 실행 성공. `DT_Tree` 2종, `DT_Axe` 9단계를 TestMap에 연결했다.
- 변경 파일의 공백 오류 검사를 통과했다.

처음 화면 출력을 끈 NullRHI 실행에서는 낚시 텍스처 크기가 0×0으로 보고되어 이미지 관련 검사가 실패했다. 실제 렌더링 실행에서는 최초 비동기 빌드의 32×32 임시 크기가 2048×1024로 바뀌는 경우까지 통과했다. 새 도끼 지급으로 빈 슬롯이 달라진 기존 농사 테스트 두 곳은 현재 시작 아이템과 실제 구버전 저장 형태에 맞춰 수정했다.

최종 기록은 `.codex-tmp/gathering-build.log`, `.codex-tmp/gathering-regression-final.log`, `.codex-tmp/gathering-smoke-final.log`에 있다. 실제 게임 검사는 별도 UserDir를 사용했다.

## 현재 경계와 다음 작업

나무는 개발용 메시이며 플레이어 전용 벌목·흔들기 애니메이션은 아직 연결하지 않았다. 벌목 후 그루터기는 유지된다. 재성장, 씨앗 식재, 나머지 수종과 지역 생성기, 채집 경험치·도감, 열매·약초·발굴은 다음 단계다. 8단계 희귀 부산물은 원본의 아이템·확률 데이터가 정해지면 연결한다.

기존 인벤토리·월드 저장은 서로 다른 파일이므로 강제 종료가 두 파일 쓰기 사이에 발생하는 경우까지 원자적으로 복원하지는 않는다. 이번에는 정상 저장·재접속과 미수집 보상 복원을 검증했다. 이후 공통 저장 스냅샷 또는 복구 기록을 도입할 때 이 경계를 함께 다루어야 한다.
